## 1. Цель работы
Освоить сопровождение ПО, автоматизацию миграции SQLite, резервное копирование, откат и подготовку эксплуатационной документации Docs-as-Code.

## 2. Регламент обновления
Выбрана стратегия Canary Deployment. Сначала обновление устанавливается на одном тестовом АРМ, затем после успешной проверки — на 5% рабочих мест, после периода наблюдения — на остальные АРМ волнами.

Перед обновлением оператор закрывает приложение, администратор останавливает процессы записи, выполняет WAL checkpoint и создает резервную копию SQLite. При критической ошибке БД восстанавливается из проверенной копии, распространение обновления останавливается. Схема процесса находится в `docs/UPDATE_FLOW.mmd`.

## 3. Разработка C# утилиты
Создана консольная утилита `CampusDbSync` на C# / .NET 8. Она создает или открывает SQLite БД, проверяет публичный API JSONPlaceholder, создает backup, считывает `PRAGMA user_version`, добавляет поля `AccessPoint` и `Status`, обновляет версию схемы, проверяет результат и формирует Markdown-отчет.

Сетевой сбой внешнего API не блокирует миграцию, так как API используется только как вспомогательная проверка. При ошибке миграции выполняется восстановление из резервной копии.

## 4. Эксплуатационная документация

## 5. Тестирование и приемка
Команда демонстрации:

```powershell
dotnet run --project .\src\CampusDbSync\CampusDbSync.csproj -- --demo
```

Ожидаемый результат: создается БД v1 с тремя записями, резервная копия, миграция до v2, сохранение строк, наличие новых колонок и отчет `sanity-report.md` со статусом PASS.

**Скриншот 1:** вывод консоли после штатного запуска.  
**Скриншот 2:** содержимое `sanity-report.md`.  
**Скриншот 3:** журнал создания backup и выполнения миграции.  
Скриншоты нужно сделать после фактического запуска; фиктивные изображения в отчет не включаются.

## 6. Вывод
Разработана утилита контролируемой миграции локальной SQLite БД АРМ. Резервное копирование, транзакции, версия схемы и sanity-проверки уменьшают риск потери исторических данных. Docs-as-Code хранит регламенты и технические решения рядом с исходным кодом и обеспечивает цифровой след сопровождения. Для промышленного внедрения необходима адаптация к фактической схеме БД и интеграция с центральным сервером доставки пакетов.
