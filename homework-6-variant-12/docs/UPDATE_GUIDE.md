# Инструкция администратора по обновлению АРМ

## 1. Стратегия доставки
Используется Canary Deployment:
1. Центральный сервер публикует пакет обновления и manifest с версией и SHA-256.
2. Установка на одном тестовом АРМ.
3. После успешной проверки — распространение на 5% рабочих мест.
4. После периода наблюдения — поэтапный rollout на остальные АРМ.
5. При критической ошибке распространение останавливается, выполняется rollback.

Для локальной SQLite БД применяется резервная копия на каждом АРМ. Blue-Green может использоваться отдельно для серверной части.

## 2. Backup
1. Уведомить оператора и закрыть основное приложение.
2. Остановить процессы, выполняющие запись в SQLite.
3. Выполнить `PRAGMA wal_checkpoint(FULL)`.
4. Скопировать SQLite в защищенный каталог backup.
5. Проверить наличие файла и ненулевой размер.
6. Зафиксировать путь, дату и размер копии.

`appsettings.json` и локальный кэш следует включить в перечень копируемых файлов конкретного АРМ, если они используются. Учебная утилита автоматизирует резервирование SQLite.

## 3. Запуск утилиты
Требуется .NET 8 SDK.

```powershell
dotnet run --project .\src\CampusDbSync\CampusDbSync.csproj -- --demo
```

Для существующей БД:

```powershell
dotnet run --project .\src\CampusDbSync\CampusDbSync.csproj -- --db "C:\ProgramData\Campus\campus.db"
```

Утилита проверяет JSONPlaceholder, создает backup, считывает `PRAGMA user_version`, добавляет `AccessPoint` и `Status`, обновляет версию схемы и формирует `reports/sanity-report.md`.

## 4. Rollback
- При ошибке внутри миграции утилита автоматически восстанавливает БД из backup.
- При обнаружении ошибки после завершения: остановить АРМ, сохранить текущую БД и лог, восстановить последнюю проверенную копию.
- Запустить приложение и проверить список проходов.
- Не удалять резервные копии до завершения периода наблюдения.

## 5. Критерии приемки
- `PRAGMA user_version` равно 2.
- `Passes` содержит `AccessPoint` и `Status`.
- Количество исторических записей не уменьшилось.
- Sanity-отчет содержит PASS.
- Проверен реальный сценарий прохода и считыватель.

## 6. Безопасность
Не записывать пароли и токены в лог. Backup хранить в каталоге с доступом только администраторам. Перед промышленным использованием проверить процедуру восстановления на тестовой копии.
